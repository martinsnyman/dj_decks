# OtoDecks

OtoDecks is a two-deck DJ application written in C++ with the [JUCE](https://juce.com/) framework. It lets you load two tracks side by side, play and mix them, shape each one with a three-band EQ, and jump around a track with saved hot cues. A central music library keeps your tracks, their BPM and their cue points between sessions.

The window has three columns: **Deck 1**, the **Music Library**, and **Deck 2**.

## Features

### Decks
Each of the two decks has:

- **Play, Stop and Load File** buttons. You can also drag and drop an audio file onto a deck.
- **Gain** slider (0 to 1).
- **Speed** slider (0.1x to 4x playback rate).
- **Position** slider that follows playback and can be dragged to seek.
- **Waveform display** with a moving playhead.
- **Three-band EQ**: low shelf at 200 Hz, mid peak at 1 kHz and high shelf at 4 kHz, each adjustable from -24 dB to +24 dB.
- **Track info**: the loaded track's name and estimated BPM.

### Hot cues
Each deck has 8 hot cue pads:

- Click an empty pad to save the current playhead position to it.
- Click a pad that has a cue to jump to that position.
- Shift-click a pad to overwrite its cue with the current position.
- **Clear Cues** removes all cues for the loaded track.

Cues are stored per track, so they come back whenever the track is loaded again, on either deck.

### Music library
- **Add Tracks** opens a file picker; you can select several files at once.
- **Remove Selected** deletes the highlighted track from the library. The audio file itself is not deleted.
- **Load -> Deck 1** and **Load -> Deck 2** load the selected track onto a deck, together with its saved cues.
- The table shows each track's name, duration, BPM and file name.
- Files loaded directly onto a deck are added to the library automatically.

### BPM detection
When a track is added, OtoDecks estimates its tempo. It analyses up to the first 60 seconds of audio, builds an energy envelope, and picks the tempo between 70 and 180 BPM that best matches the envelope's repeating pattern (autocorrelation). The result is an estimate, so expect occasional half- or double-tempo readings.

### Saved state
The library, each track's hot cues and both decks' EQ settings are saved automatically to `otodecks_state.json` in an `OtoDecks` folder inside your user application-data directory (for example `%APPDATA%\OtoDecks` on Windows). They are restored the next time the app starts.

## Supported audio formats
WAV, AIFF, FLAC and Ogg Vorbis. MP3 is supported in the Projucer build, which enables JUCE's MP3 decoder.

## Building

### Requirements
- JUCE 8, checked out in a folder named `JUCE` next to this project:
  ```
  Final Project/
  ├── JUCE/
  └── OtoDecks-Lourens-Snyman/   (this repository)
  ```
- A supported C++ toolchain: Visual Studio 2022 on Windows, Xcode on macOS, or GCC/Clang on Linux. MinGW is not supported by JUCE.

### With the Projucer
1. Open `OtoDecks.jucer` in the Projucer, the JUCE project tool.
2. Save the project to generate the IDE projects in `Builds/`.
3. Open the generated project (for example `Builds/VisualStudio2022/OtoDecks.sln`), then build and run.

### With CMake
```sh
cmake -B build
cmake --build build --config Release
```
`CMakeLists.txt` expects JUCE at `../JUCE`.

## Project structure

| File | Purpose |
| --- | --- |
| `Source/Main.cpp` | Application entry point and main window. |
| `Source/MainComponent.*` | Top-level component: audio mixer, both decks, the music library table, BPM detection and saving/loading state. |
| `Source/DeckGUI.*` | User interface for one deck: transport buttons, sliders, EQ, hot cues and drag-and-drop. |
| `Source/DJAudioPlayer.*` | Audio engine for one deck: file playback, gain, speed, seeking and the three-band EQ filter chain. |
| `Source/WaveformDisplay.*` | Waveform view with a playhead marker. |
| `JuceLibraryCode/` | Code generated by the Projucer. |
| `OtoDecks.jucer` | Projucer project file. |
